Data Engineering — WSL & Linux Command-Line

The practical assessment will very likely run inside WSL (Windows Subsystem for Linux). This module drills awk, sed, grep, cat, pipes, and process management — everything a CTO must wield fluently when SSH’d into a production Ubuntu server or processing data on a headless edge gateway.

Preparation Progress 0 / 0
CV Grounding
  • SESKA HPC (Rocky Linux / Slurm): You work daily in a Linux terminal — compiling C++/Fortran with GNU toolchain, running OpenMPI jobs, navigating POSIX filesystems. This is not theoretical for you.
  • SEAT Django on Ubuntu: Deployed Django behind Gunicorn + Nginx on Ubuntu VMs. Managed services with systemctl, monitored logs with journalctl and tail -f.
  • ComputeMore CI/CD: GitHub Actions runners operate in Ubuntu containers. You write bash scripts for build/deploy pipelines.

💻 WSL Setup & Verification

Environment Preparation
  • Verify WSL2 + Ubuntu is installed and updated
    In PowerShell: wsl --list --verbose — confirm Ubuntu is version 2. Inside WSL: sudo apt update && sudo apt upgrade -y. Install essentials: sudo apt install -y build-essential python3 python3-pip python3-venv git curl wget jq tree.
  • Set up Python virtual environment in WSL
    python3 -m venv ~/assessment-env && source ~/assessment-env/bin/activate. Then: pip install django flask pandas numpy psycopg2-binary paho-mqtt gunicorn. Verify: python3 -c "import django; print(django.get_version())". Pre-install now to avoid pip downloads during the assessment.
  • Install PostgreSQL natively in WSL
    sudo apt install -y postgresql postgresql-contrib postgis. Start: sudo service postgresql start. Create user: sudo -u postgres createuser --superuser $USER. Create database: createdb assessment_db. Verify PostGIS: psql assessment_db -c "CREATE EXTENSION postgis; SELECT PostGIS_Version();". This gives you a native DB without Docker.

⌨ Core Unix Commands (Drill These)

These are the bread-and-butter commands for data inspection and transformation. Practice until they are muscle memory.

cat, head, tail, wc — Inspection
  • Practice: Inspect CSV files without opening an editor
    cat data.csv                    # dump (pipes well)
head -n 5 data.csv              # first 5 lines (check header)
tail -n 20 data.csv             # last 20 lines (check recent data)
tail -f /var/log/syslog         # live-stream logs
wc -l data.csv                  # line count (row count)
wc -w data.csv                  # word count
file data.csv                   # encoding & type (UTF-8? ASCII?)
    Practice site: cmdchallenge.com — interactive command-line puzzles.
grep — Pattern Search
  • Drill: grep patterns for data filtering
    # Find all lines containing "ERROR" in Django logs
grep "ERROR" /var/log/django/app.log

# Case-insensitive search
grep -i "warning" app.log

# Count occurrences
grep -c "ERROR" app.log

# Show line numbers
grep -n "IntegrityError" app.log

# Regex: find GPS pings with speed > 100 (3-digit speeds)
grep -E '"speed":\s*[1-9][0-9]{2}' gps_data.json

# Invert match: show lines WITHOUT "DEBUG"
grep -v "DEBUG" app.log

# Recursive search in project directory
grep -rn "DATABASES" ~/myproject/
    Practice site: regexr.com — build and test regex patterns interactively.
  • Practice: grep through Django project files
    # Find all models inheriting from models.Model
grep -rn "class.*models.Model" myproject/

# Find all URL patterns
grep -rn "path(" myproject/urls.py

# Find all database queries (raw SQL)
grep -rn "raw\|execute\|cursor" myproject/

# Find all imports of a specific module
grep -rn "from django.db" myproject/

# Find settings that reference a specific env var
grep -rn "os.environ" myproject/settings/
awk — Column Processing
  • Drill: awk for CSV column extraction and computation
    # Print 2nd column (vehicle_id) from CSV
awk -F',' '{print $2}' gps_data.csv

# Print columns 2 and 5 (vehicle_id, speed)
awk -F',' '{print $2, $5}' gps_data.csv

# Filter: only rows where speed (col 5) > 80
awk -F',' '$5 > 80 {print $0}' gps_data.csv

# Compute average of column 5 (speed)
awk -F',' 'NR>1 {sum+=$5; n++} END {print "avg:", sum/n}' gps_data.csv

# Count unique vehicle IDs
awk -F',' 'NR>1 {ids[$2]++} END {for(id in ids) print id, ids[id]}' gps_data.csv

# Sum total distance (column 6)
awk -F',' 'NR>1 {sum+=$6} END {printf "Total: %.2f km\n", sum}' trips.csv
    Practice site: awk.js.org — run awk in the browser with sample data.
  • Practice: awk for Django/Gunicorn access log analysis
    # Parse Gunicorn access log: count requests per status code
awk '{print $9}' access.log | sort | uniq -c | sort -rn

# Find slowest endpoints (>2 seconds)
awk '$NF > 2.0 {print $7, $NF "s"}' access.log

# Requests per IP address
awk '{print $1}' access.log | sort | uniq -c | sort -rn | head -10

# Extract just 500 errors with their URLs
awk '$9 == 500 {print $1, $7, $9}' access.log
sed — Stream Editing
  • Drill: sed for in-place text transformation
    # Replace all "localhost" with production hostname
sed -i 's/localhost/db.uct.ac.za/g' settings.py

# Delete blank lines
sed -i '/^$/d' data.csv

# Delete header line (line 1)
sed '1d' data.csv > data_no_header.csv

# Insert a new header
sed -i '1i vehicle_id,lat,lon,speed,timestamp' data.csv

# Replace only on lines matching a pattern
sed '/DEBUG/s/True/False/' settings.py

# Remove carriage returns (Windows → Unix line endings)
sed -i 's/\r$//' data.csv

# Extract lines 100–200
sed -n '100,200p' large_file.csv
    Practice site: sed.js.org — interactive sed playground.
  • Practice: sed for Django config and deployment scripting
    # Toggle DEBUG in Django settings
sed -i 's/^DEBUG = True/DEBUG = False/' myproject/settings.py

# Update ALLOWED_HOSTS
sed -i "s/ALLOWED_HOSTS = \[\]/ALLOWED_HOSTS = ['*']/" settings.py

# Swap database engine from SQLite to PostgreSQL
sed -i "s/'django.db.backends.sqlite3'/'django.db.backends.postgresql'/" settings.py

# Bulk-update import paths after refactoring
sed -i 's/from app.old_module/from app.new_module/g' *.py
Pipes & Composition
  • Master the pipe philosophy: chain small tools into powerful pipelines
    # Complete data pipeline in one line:
# 1. Skip header  2. Extract speed col  3. Sort  4. Get top 10
tail -n +2 gps_data.csv | awk -F',' '{print $5}' | sort -rn | head -10

# Count unique vehicles that exceeded 100 km/h
awk -F',' '$5 > 100 {print $2}' gps_data.csv | sort -u | wc -l

# Find Django migration files modified in the last 7 days
find . -name "*.py" -path "*/migrations/*" -mtime -7 | sort

# Monitor Django logs and filter for errors in real time
tail -f django.log | grep --line-buffered "ERROR"

# Generate a quick data summary
echo "Rows: $(wc -l < data.csv)" && \
echo "Columns: $(head -1 data.csv | awk -F',' '{print NF}')" && \
echo "Size: $(du -h data.csv | cut -f1)"

🚀 Bash Data Processing Pipelines

Sometimes you need to process data before it reaches Python. Bash pipelines are 10–100× faster than Python for simple transformations on large files.

Real-World Pipeline Exercises
  • Exercise: Clean a 1M-row CSV using only CLI tools (10 min)
    # Generate test data
python3 -c "
import csv, random
with open('raw.csv','w') as f:
    w = csv.writer(f)
    w.writerow(['id','vehicle','lat','lon','speed','ts'])
    for i in range(1000000):
        w.writerow([i, f'V-{random.randint(1,20):02d}',
                     -33.93+random.gauss(0,0.01),
                     18.42+random.gauss(0,0.01),
                     random.gauss(45,15),
                     f'2026-03-12T{random.randint(0,23):02d}:{random.randint(0,59):02d}:00Z'])
"

# Clean pipeline:
# 1. Remove header  2. Filter valid speeds  3. Remove dupes  4. Sort by timestamp
tail -n +2 raw.csv | \
  awk -F',' '$5 > 0 && $5 < 150' | \
  sort -t',' -k6 -u | \
  sed '1i id,vehicle,lat,lon,speed,ts' > clean.csv

echo "Raw: $(wc -l < raw.csv) rows"
echo "Clean: $(wc -l < clean.csv) rows"
  • Exercise: Pipe cleaned CSV directly into PostgreSQL
    # Create table
psql assessment_db -c "
CREATE TABLE IF NOT EXISTS gps_pings (
  id INT, vehicle TEXT, lat DOUBLE PRECISION,
  lon DOUBLE PRECISION, speed FLOAT, ts TIMESTAMPTZ
);"

# Bulk-load using COPY from stdin
tail -n +2 clean.csv | psql assessment_db -c "\COPY gps_pings FROM STDIN WITH CSV"

# Verify
psql assessment_db -c "SELECT COUNT(*), AVG(speed) FROM gps_pings;"
    This is the fastest way to load data into PostgreSQL — 10× faster than Python row-by-row inserts.
  • Exercise: Transform data between formats (JSON ↔ CSV)
    # CSV to JSON Lines (one JSON object per line)
awk -F',' 'NR>1 {printf "{\"vehicle\":\"%s\",\"lat\":%s,\"lon\":%s,\"speed\":%s}\n",$2,$3,$4,$5}' clean.csv > data.jsonl

# JSON Lines to CSV (using jq)
cat data.jsonl | jq -r '[.vehicle,.lat,.lon,.speed] | @csv' > back_to_csv.csv

# Pretty-print JSON
cat data.jsonl | head -1 | python3 -m json.tool
    Install jq: sudo apt install jq — the awk of JSON. Essential tool.

💬 Key Talking Points

Technical

Speed: awk processes a 1 GB CSV in ~10 seconds. Python Pandas loads the same file in ~45 seconds. For column extraction and simple filtering, CLI tools are 5–10× faster because they’re compiled C programs with zero startup overhead.

Composability: Unix pipes let you chain tools without intermediate files. grep | awk | sort | uniq -c builds complex transformations from simple primitives. Each tool does one thing well.

Universality: These tools exist on every Linux server, every Docker container, every cloud VM. No pip install needed. When you SSH into a production server at 2 AM to debug, grep and awk are always there.

Your evidence: “On the UCT HPC cluster running SESKA, I use grep/awk/sed daily to parse Slurm job output, monitor MPI process logs, and pre-process input files for the FE solver. It’s not optional in HPC — it’s how you operate.”
