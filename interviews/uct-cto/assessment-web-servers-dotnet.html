Web Servers — ASP.NET Core, Nginx & Apache

A CTO must be comfortable deploying and configuring web servers beyond the Python ecosystem. This module covers ASP.NET Core (C# web framework), Nginx (reverse proxy and static server), and Apache (traditional web server) — the trio that powers most enterprise Linux deployments.

Preparation Progress 0 / 0
CV Grounding
  • SEAT + Nginx: The SEAT platform runs Django behind Gunicorn with Nginx as the reverse proxy. You configure Nginx server blocks, TLS certificates, and static file serving in production.
  • ComputeMore (.NET): While the current stack is Nuxt.js, the enterprise API architecture uses ASP.NET Core patterns. C# is your strongest language alongside Python.
  • UCT Infrastructure: University systems often run on Apache (legacy) and Nginx (modern). As CTO, you’ll manage both.

🛡️ Nginx — Reverse Proxy & Web Server

Nginx is the most common reverse proxy for Python and .NET applications. Know it cold.

Installation & Core Configuration 
  • # Install
sudo apt install -y nginx

# Start / enable
sudo systemctl start nginx
sudo systemctl enable nginx

# Verify
curl -s http://localhost | head -5
# Should show "Welcome to nginx!"

# Key directories:
# /etc/nginx/nginx.conf          - main config
# /etc/nginx/sites-available/    - virtual host configs
# /etc/nginx/sites-enabled/      - symlinks to active configs
# /var/log/nginx/access.log      - access logs
# /var/log/nginx/error.log       - error logs
  • # /etc/nginx/sites-available/transport_api
server {
    listen 80;
    server_name transport.uct.ac.za;

    # Security headers
    add_header X-Frame-Options DENY;
    add_header X-Content-Type-Options nosniff;
    add_header X-XSS-Protection "1; mode=block";

    # Static files (served directly by Nginx)
    location /static/ {
        alias /opt/transport_api/staticfiles/;
        expires 30d;
        add_header Cache-Control "public, immutable";
    }

    location /media/ {
        alias /opt/transport_api/media/;
    }

    # Proxy all other requests to Gunicorn
    location / {
        proxy_pass http://unix:/run/gunicorn.sock;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_redirect off;

        # Timeouts
        proxy_connect_timeout 60s;
        proxy_read_timeout 120s;
    }

    # Health check endpoint
    location /health {
        proxy_pass http://unix:/run/gunicorn.sock;
        access_log off;
    }
}

# Enable the site
sudo ln -s /etc/nginx/sites-available/transport_api /etc/nginx/sites-enabled/
sudo nginx -t         # Test config
sudo systemctl reload nginx
    Docs: Nginx Beginner’s Guide. 
  • # /etc/nginx/sites-available/dotnet_api
server {
    listen 80;
    server_name api.uct.ac.za;

    location / {
        proxy_pass http://localhost:5000;  # Kestrel default port
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection keep-alive;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
    }
}

# Key difference from Gunicorn:
# - Kestrel uses TCP port (localhost:5000), not Unix socket
# - ASP.NET handles its own worker threads internally
# - proxy_http_version 1.1 is needed for WebSocket support

sudo apt install -y certbot python3-certbot-nginx

# Obtain and auto-configure certificate
sudo certbot --nginx -d transport.uct.ac.za

# Certbot modifies your Nginx config to add:
# listen 443 ssl;
# ssl_certificate /etc/letsencrypt/live/...;
# ssl_certificate_key /etc/letsencrypt/live/...;
# Redirect HTTP → HTTPS

# Auto-renewal (already set up by Certbot)
sudo certbot renew --dry-run

# Manual renewal cron (if needed)
# 0 3 * * 1 certbot renew --post-hook "systemctl reload nginx"
Load Balancing & Rate Limiting 
  • # Load balance across multiple Gunicorn/Kestrel instances
upstream backend {
    # Round-robin (default)
    server 127.0.0.1:8001;
    server 127.0.0.1:8002;
    server 127.0.0.1:8003;
    
    # Weighted
    # server 127.0.0.1:8001 weight=3;
    # server 127.0.0.1:8002 weight=1;
    
    # Least connections
    # least_conn;
    
    # IP hash (sticky sessions)
    # ip_hash;
}

server {
    listen 80;
    location / {
        proxy_pass http://backend;
    }
}

# Rate limiting
limit_req_zone $binary_remote_addr zone=api:10m rate=10r/s;

server {
    location /api/ {
        limit_req zone=api burst=20 nodelay;
        proxy_pass http://backend;
    }
}

🔧 Apache — Traditional Web Server

Apache is still common at universities and government servers. Know the basics even if you prefer Nginx.

Apache Configuration
  • # Install
sudo apt install -y apache2

# Enable required modules
sudo a2enmod proxy proxy_http proxy_balancer lbmethod_byrequests
sudo a2enmod rewrite headers ssl

# Start
sudo systemctl start apache2

# Key directories:
# /etc/apache2/apache2.conf            - main config
# /etc/apache2/sites-available/        - virtual host configs
# /etc/apache2/sites-enabled/          - symlinks to active configs
# /var/log/apache2/access.log
# /var/log/apache2/error.log
  • # /etc/apache2/sites-available/transport_api.conf
<VirtualHost *:80>
    ServerName transport.uct.ac.za

    # Security headers
    Header always set X-Frame-Options DENY
    Header always set X-Content-Type-Options nosniff

    # Static files
    Alias /static/ /opt/transport_api/staticfiles/
    <Directory /opt/transport_api/staticfiles/>
        Require all granted
        Options -Indexes
    </Directory>

    # Reverse proxy to Gunicorn
    ProxyPreserveHost On
    ProxyPass /static/ !
    ProxyPass / http://127.0.0.1:8000/
    ProxyPassReverse / http://127.0.0.1:8000/

    # Logging
    ErrorLog ${APACHE_LOG_DIR}/transport_error.log
    CustomLog ${APACHE_LOG_DIR}/transport_access.log combined
</VirtualHost>

# Enable
sudo a2ensite transport_api
sudo apache2ctl configtest  # Test config
sudo systemctl reload apache2
  • # /etc/apache2/sites-available/dotnet_api.conf
<VirtualHost *:80>
    ServerName api.uct.ac.za

    ProxyPreserveHost On
    ProxyPass / http://127.0.0.1:5000/
    ProxyPassReverse / http://127.0.0.1:5000/

    # WebSocket support (if needed)
    RewriteEngine On
    RewriteCond %{HTTP:Upgrade} websocket [NC]
    RewriteCond %{HTTP:Connection} upgrade [NC]
    RewriteRule /(.*) ws://127.0.0.1:5000/$1 [P,L]

    ErrorLog ${APACHE_LOG_DIR}/dotnet_error.log
    CustomLog ${APACHE_LOG_DIR}/dotnet_access.log combined
</VirtualHost>

    Architecture Event-driven (async) Process/thread per request
    Concurrent connections Excellent (10K+) Good (1K–5K)
    Static files Very fast Fast
    .htaccess support No Yes (per-directory config)
    Module system Compiled in Dynamic (a2enmod)

💎 ASP.NET Core — C# Web Framework

ASP.NET Core runs on Linux via .NET SDK. It’s cross-platform, high-performance, and uses Kestrel as its built-in web server.

Setup & Scaffolding
  • # Install .NET SDK 8
wget https://dot.net/v1/dotnet-install.sh -O dotnet-install.sh
chmod +x dotnet-install.sh
./dotnet-install.sh --channel 8.0
export PATH="$HOME/.dotnet:$PATH"

# Or via apt:
# sudo apt install -y dotnet-sdk-8.0

# Verify
dotnet --version

# Scaffold a Web API
dotnet new webapi -n TransportApi -o ~/transport-api-dotnet
cd ~/transport-api-dotnet
dotnet run
# Listening on http://localhost:5000

# Key concepts:
# - Kestrel = built-in web server (like Gunicorn for Python)
# - Entity Framework = ORM (like Django ORM)
# - DbContext = database session manager
# - Dependency Injection = first-class citizen in ASP.NET Core
Minimal API (Fast Prototyping)
  • // Program.cs - ASP.NET Core Minimal API
using Microsoft.EntityFrameworkCore;
using System.ComponentModel.DataAnnotations;

var builder = WebApplication.CreateBuilder(args);

// Register DbContext with PostgreSQL
builder.Services.AddDbContext<TransportDb>(opt =>
    opt.UseNpgsql(builder.Configuration.GetConnectionString("Default")));

var app = builder.Build();

// GET /api/vehicles
app.MapGet("/api/vehicles", async (TransportDb db) =>
    await db.Vehicles.ToListAsync());

// GET /api/vehicles/{id}/pings
app.MapGet("/api/vehicles/{id}/pings", async (int id, TransportDb db) =>
    await db.GPSPings.Where(p => p.VehicleId == id)
                     .OrderByDescending(p => p.Timestamp)
                     .Take(100).ToListAsync());

// POST /api/pings
app.MapPost("/api/pings", async (GPSPing ping, TransportDb db) => {
    db.GPSPings.Add(ping);
    await db.SaveChangesAsync();
    return Results.Created($"/api/pings/{ping.Id}", ping);
});

app.Run();

// Models & DbContext
public class Vehicle {
    public int Id { get; set; }
    [MaxLength(20)] public string VehicleId { get; set; } = "";
    public string VehicleType { get; set; } = "";
    public bool IsActive { get; set; } = true;
}

public class GPSPing {
    public int Id { get; set; }
    public int VehicleId { get; set; }
    public double Lat { get; set; }
    public double Lon { get; set; }
    public double Speed { get; set; }
    public DateTime Timestamp { get; set; }
}

public class TransportDb : DbContext {
    public TransportDb(DbContextOptions<TransportDb> options) : base(options) { }
    public DbSet<Vehicle> Vehicles => Set<Vehicle>();
    public DbSet<GPSPing> GPSPings => Set<GPSPing>();
}
Deployment as a Linux Service
  • # Build for production
dotnet publish -c Release -o /opt/transport-api-dotnet

# /etc/systemd/system/kestrel-transport.service
[Unit]
Description=ASP.NET Core Transport API
After=network.target postgresql.service

[Service]
WorkingDirectory=/opt/transport-api-dotnet
ExecStart=/usr/bin/dotnet /opt/transport-api-dotnet/TransportApi.dll
Restart=always
RestartSec=10
KillSignal=SIGINT
SyslogIdentifier=transport-api
User=www-data
Environment=ASPNETCORE_ENVIRONMENT=Production
Environment=ASPNETCORE_URLS=http://localhost:5000
Environment=ConnectionStrings__Default=Host=localhost;Database=transport_db;Username=django

[Install]
WantedBy=multi-user.target

# Enable and start
sudo systemctl daemon-reload
sudo systemctl enable kestrel-transport
sudo systemctl start kestrel-transport

# Check status
sudo systemctl status kestrel-transport
journalctl -u kestrel-transport --since "5 min ago"

// Remember: Kestrel should NOT be exposed directly to the internet.
// Always put Nginx or Apache in front as a reverse proxy.

🏗️ Full Deployment Stack (Putting It All Together)

Architecture Diagram
  • === Django Stack ===
Client → Nginx (TLS, static files)
           → Gunicorn (WSGI, workers)
              → Django (views, ORM)
                 → PostgreSQL + PostGIS

=== ASP.NET Stack ===
Client → Nginx (TLS, static files)
           → Kestrel (built-in, async)
              → ASP.NET Core (controllers, EF Core)
                 → PostgreSQL

=== Shared Infrastructure ===
PostgreSQL: shared database server
Nginx: shared reverse proxy (multiple server blocks)
systemd: manages both Gunicorn and Kestrel services
Let's Encrypt: TLS certificates for both

💬 Key Talking Points

Technical

Defense in depth. Kestrel is an application server optimised for running C# code fast. Nginx is a battle-tested internet-facing server optimised for handling thousands of concurrent connections, TLS termination, request buffering (protecting against slow clients), static file serving, and rate limiting.

Without Nginx, a slow client uploading a 100 MB file would tie up a Kestrel thread for minutes. Nginx buffers the entire request before forwarding it to Kestrel in one fast internal transfer. Microsoft’s own documentation recommends this architecture for production deployments.

Analogy: Nginx is the bouncer at the door. Kestrel is the bartender. You don’t make the bartender check IDs.

Leadership

UCT runs a mix. Legacy systems (student portals, HR) are often on Apache behind F5 load balancers. Newer services (SEAT, research platforms) use Nginx. As CTO, the strategic direction is:

  • Standardise on Nginx for new deployments — better concurrency model, simpler config syntax
  • Maintain Apache where migration cost > benefit (legacy .htaccess-dependent apps)
  • Containerise where possible — Nginx as ingress controller in Kubernetes
  • Enforce TLS everywhere via automated certificate management (cert-manager or Certbot)
