### Responsive images and presentation export

- [`scripts/optimize-images.py`](../scripts/optimize-images.py) produces `25`
  responsive WebP variants for nine homepage assets, without replacing originals.
  Widths are capped at each source size. The homepage adds `srcset`, `sizes`,
  explicit dimensions and asynchronous decoding; the hero has high fetch priority
  and eight later images use lazy loading.
- The largest selected homepage variants total `528,868` bytes versus `3,759,069`
  original bytes, an `85.9%` reduction. All homepage variants total `953,166` bytes;
  the distinction avoids presenting the complete asset folder as a page transfer.
- Addressed `A5` with
  [`scripts/optimize-presentation.py`](../scripts/optimize-presentation.py): `45`
  WebP variants for `18` active presentation images, at quality `90`, with smaller
  cover-image sizes and figure widths up to `2400px`. All originals, including
  scientific diagrams, remain intact. Dimensions reserve layout space; eight
  cover images load eagerly and ten later images load lazily.
- The largest presentation variants total **`724,320` bytes**, compared with
  **`30,952,859` bytes** of originals: **`97.7%` smaller**. All `45` variants total
  `1,479,314` bytes. A local desktop load without scrolling transferred `92,828`
  encoded image-body bytes; this is a local Chromium observation, not a measured
  production speed or Core Web Vitals improvement.
- Each presentation image retains `data-print-src`. PDF export switches to the
  originals, eagerly loads and decodes them, waits for fonts, and restores the
  responsive attributes in `finally`. Image loading has a `30,000ms` timeout;
  failure restores the download control and reports a retryable error.
- An actual export attempt exposed the cost of rasterizing the entire long deck
  in one canvas. Export now renders each section sequentially, reuses the PDF,
  releases intermediate canvas storage and reports section progress. Long
  sections retain pagination; page-break avoidance protects common cards,
  figures, equations and tables when they fit. State is restored after either
  exporter success or failure.
- A real download completed as a `21`-page, `11,932,865`-byte PDF. All pages were
  rendered for visual inspection and scientific figures remained present. The
  existing export remains rasterized and untagged; long sections span pages.

### Compatibility and deployment notes

- The site remains static HTML/CSS/JavaScript on existing public paths. Ship the
  updated HTML with its shared scripts, styles, tokens and responsive assets;
  copying only HTML would leave missing dependencies. No database migrations,
  API contracts or application version changes are involved.
- Local UI checks require Node.js, the installed Playwright development package
  and a compatible Chrome channel. Static hosting does not require these tools.
  Python documentation builds require the packages in `requirements-docs.txt`;
  optional image regeneration additionally requires Pillow and `cwebp`.
- Assessment persistence keeps the existing storage/item keys. Corrupt or blocked
  local storage falls back to usable in-memory interaction. Static content remains
  readable when JavaScript or optional highlighting/math libraries are unavailable.
- The Pages workflow expects the sibling `system-management_scripts` checkout.
  That checkout was absent locally, so full source synchronization and deployment
  were not run. The local `--no-sync` build is not evidence of a successful release.
- Original image assets remain available for high-resolution export. WebP files
  add a derived asset set; the measured reduction concerns selected browser
  sources, not total repository size. Screenshot PNGs are intentionally local.
