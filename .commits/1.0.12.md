### Homepage hero: interactive computational mesh

- The hero heading is now `Complexity, functionality, abstraction.`
  (`#hero-title`, referenced by `aria-labelledby` on `section.hero`). The
  portrait column (`.hero-portrait`, `.portrait-frame`, `.hero-socials`,
  `.social-button*`, `.status-dot`) is replaced by `figure.mesh-study`.
- New module [`scripts/mesh.mjs`](../scripts/mesh.mjs) (175 lines, loaded as
  `type="module"`) exports `renderMesh(imprints = [])`:
  - It samples a 72 × 12 parametric surface into quadrilateral faces, projected
    into a `620 × 550` view box and sorted by depth.
  - Each imprint `{x, y, strength}` adds a Gaussian dent (σ = 74 px), so nearby
    mesh lines stay connected.
  - The file notes that the surface is illustrative, not a physical simulation.
  - The same function generates the static fallback
    [`assets/computational-mesh.svg`](../assets/computational-mesh.svg).
- Interaction on `svg.mesh-interactive` (`role="img"`, `tabindex="0"`):
  - **Pointer:** pressing on a polygon adds an imprint of strength 18. Dragging
    adds strength-8 imprints at least 16 px apart. At most 36 imprints are kept;
    the oldest is dropped.
  - **Pinch:** two pointers zoom by their change in distance, centred between
    them.
  - **Wheel:** zooms by `Math.exp(-deltaY * 0.001)`, centred on the cursor. The
    listener is non-passive so it can stop the page from scrolling.
  - **Keyboard:** `+`/`=` zooms in and `-`/`_` zooms out (factor 1.15). `Enter`
    or `Space` dents the centre.
  - Zoom is limited to `0.65`–`2.8` and applied as a `transform` on
    `[data-mesh-surface]`. Redraws are batched to animation frames.
- Progressive enhancement: once the module runs, it adds `.is-interactive` to
  the figure. That hides `.mesh-fallback` and shows `.mesh-interactive` and
  `.mesh-hint`. Without JavaScript, the `<img>` fallback with alt text stays
  visible. `.mesh-axis` draws a decorative x/y/z axis.
- New `.hero-intro`, `.hero-person` (Cape Town location line) and
  `.hero-actions`. The primary action is now `button button-primary`, replacing
  `.button-dark`. The secondary link now goes to GitHub
  (`target="_blank" rel="noopener noreferrer"`). The résumé link is kept in the
  source as an HTML comment.

### Compatibility and deployment notes

- The site is still static HTML/CSS/JavaScript on GitHub Pages, and all public
  routes are unchanged. There is no database, API or package version.
- Generated docs now link `/docs-styles.css`, and `/styles.css` no longer
  exists. Any external link or cached page that points to `/styles.css` will
  load without styles. Deploy the regenerated `docs/**` together with
  `docs-styles.css`.
- The Pages workflow no longer pulls in `system-management_scripts`. Guide
  updates must be committed to this repository (or built locally without
  `--no-sync`) before they are deployed.
- `scripts/mesh.mjs` needs ES module support. Browsers without it, or without
  JavaScript, show the static SVG.
- **Remote tags and releases are not yet changed.** The old tags `13dec25`,
  `05apr26`, `06apr26`, `22apr26`, `17jul26`, `18jul26`, `20aug26` and `13oct26`
  still exist on `origin`. GitHub releases are attached to six of them
  (`05apr26`, `06apr26`, `17jul26`, `18jul26`, `20aug26`, `13oct26`).
  Publishing the rename means pushing the `1.0.x` tags, moving each release to
  its new tag, and then deleting the old remote tags.
